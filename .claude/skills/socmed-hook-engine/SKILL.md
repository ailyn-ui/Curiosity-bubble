# Hook Engine

The first line decides whether anything else gets read. Two posts with the same value and the same audience can perform wildly differently on the hook alone, and a strong hook almost always comes from three things: knowing exactly who's reading, saying something specific, and giving a reason to keep going right now.

This skill writes hooks from what the user has: their audience, their customers' words, their real proof, and what they know that others miss. It picks hook patterns that fit that material, writes a varied batch, scores every hook, and throws out the weak ones before the user sees them.

## The one rule that overrides everything

**Never invent proof.** No made-up numbers, client results, revenue, follower counts, credentials, studies, or personal stories. People post these hooks under their own name, and a fabricated "I went from $0 to $40K" can cost them their reputation, or break the law in regulated industries.

- Use only proof that's in the Content Profile or that the user gave you in this conversation.
- When a pattern needs a detail you don't have, write a bracketed placeholder, like `[your real client result]`, and flag it under the hook.
- If the user has no proof yet, that's fine. Eight of the 12 patterns need none, so lean on those.

## Modes

| The user wants | Mode |
|---|---|
| Hooks for a topic, post, video, email, or offer | **Hook batch** (default) |
| Sign-ups, registrations, clicks, or purchases, or asks for a headline and subheadline | **Conversion mode** |
| Pastes a hook or first line and asks if it's good, or asks to fix it | **Hook doctor** |
| Pastes DMs, reviews, testimonials, a sales-call transcript, or comments | **Mine my customers** |
| First use, no profile, or "set up hook engine" | **Setup** |

Pick the most likely mode and go. Don't ask which mode they want.

## Step 0: Find the profile

Look for a block titled `CONTENT PROFILE` (or an older `POST VALUE FILTER PROFILE`) in the conversation, the project instructions, or the user's saved preferences.

- **Found it:** use it silently. Don't recite it back.
- **Not found, first time:** run Setup using `references/setup-interview.md`. It takes about two minutes and ends with a profile block the user saves.
- **Not found, and they want hooks now:** ask the three quick-start questions from `references/setup-interview.md` in one message, write the batch, then offer full setup in one line at the end.
- **They refuse all questions:** infer what you can from their request, write the batch, and mark it "Uncalibrated" at the top so they know the hooks could be sharper.

On top of the profile, you need to know **the topic** (what this specific piece is about), **the platform**, and **the goal** (reach, engagement, authority, or conversion). If the topic is missing, ask. If the platform or goal is missing, assume Instagram and reach, state that assumption in the header, and go.

## Hook batch

### 1. Take inventory

Before writing, sort the material you have into the categories below. This decides which patterns you're allowed to use.

| Material | Where it comes from |
|---|---|
| Real result or number | "My real proof," or the user's message |
| Personal story | "My real proof" (a low point, a turning point, a mistake) |
| Credential | "My real proof" (years, clients served, qualifications) |
| Client story | "My real proof," with permission |
| Contrarian take or mechanism | "What I know that others miss" |
| Customer language | "Her words," or pasted messages |
| Opinions and expertise | Everyone has this |

### 2. Choose the patterns

The 12 patterns, their formulas, what each one requires, and examples across industries are in `references/architectures.md`. Read it before your first batch in a conversation.

- Use only patterns whose "Requires" is met by the inventory.
- Use **at least 5 different patterns** in a batch. If fewer than 5 are available because proof is thin, use every available pattern, and tell the user which material would unlock more ("Share one client result and I can add Before/After and Credential Bridge hooks").
- Prioritize by goal:
  - **Reach and shares:** Start-Over Plan, Wrong Answer, Signs You're, Bold Declaration
  - **Connection and trust:** Low Point, Honest Admission, Her Exact Words
  - **Authority:** Credential Bridge, Before/After, Rating
  - **Comments and debate:** Rating, Hot Seat, Wrong Answer
  - **Leads and conversion:** Mistake Warning, Before/After, Her Exact Words

### 3. Write the batch

Write **10 hooks** by default (5 if they ask for a quick batch, more if they ask). Every hook must deliver three things within the first three seconds of reading or watching:

1. **Who it's for.** The reader recognizes herself, whether it's stated or implied.
2. **What she'll get.** A list, a story, a breakdown, a rating, a result. She knows what shape the value arrives in.
3. **Why now.** A specific number, a real moment, a surprising claim, or a stake. Something that makes her stop instead of saving it for later.

Rules for every hook:

- **Front-load the charged word.** The most surprising or emotional word goes in the first three words whenever possible.
- **No throat-clearing.** Cut "Today I want to talk about," "Let me share," "So, I've been thinking," "Here's the thing." Start with the hook.
- **Provoke before you explain.** Tension, proof, or surprise first, context after.
- **Specific beats vague.** A number beats "a lot," a timeframe beats "quickly," and "restaurant owners at month-end" beats "business owners."
- **Use her words.** When the profile has customer language, at least two hooks in the batch should be built on it.
- **Fit the visible window.** Written hooks must land their punch before the platform's "more" cutoff. Limits are in `references/platforms.md`.
- **Sound like a person.** No em dashes (unless the user's own voice uses them), and none of: unlock, elevate, game-changer, journey, navigate, delve, "let that sink in," "read that again," "nobody is talking about this." Match the voice in the profile.
- **Respect the "never say" list** and any compliance limits, every time.

### 4. Check diversity

Before scoring, read the batch back to back.

- If two hooks follow the same formula (for example, "states a problem, then says a tool fixed it fast"), replace one with a different pattern.
- The same proof point can appear in no more than two hooks. Rotate the rest.
- Vary the first word. No more than two hooks should start the same way.
- Test: a stranger who reads hooks 1 through 4 shouldn't be able to predict the shape of hook 5.

### 5. Score every hook

Score each hook on five tests, 1 point each:

| Test | Passes when |
|---|---|
| **Relevance** | Her exact reader would stop because it feels written for her, not for everyone. |
| **Specificity** | There's a real number, a named audience, a concrete moment, or a specific outcome. |
| **Tension** | There's a contrast, surprise, conflict, or open loop she needs to close. |
| **Speed** | The charged word lands in the first three words. No warm-up. |
| **Pull** | She needs to see what comes next. |

Only show hooks scoring **4 or 5**. Rewrite anything at 3 or below until it passes, or cut it and write a new one. Be strict. A hook you wouldn't personally stop for doesn't pass.

Then run the **truth check**: every claim in every hook comes from the profile or the user's message, or it's a flagged placeholder. No exceptions.

### 6. Output

```
HOOK BATCH · [topic] · [platform] · goal: [goal]

1. [PATTERN NAME] · 5/5
Written: "[hook, within the platform's visible window]"
Spoken: "[video opener, 2-3 sentences, only for video platforms or if asked]"
Why it works: [one line]
Proof used: [the profile item, or "none needed," or "⚠ fill in [placeholder]"]

2. [PATTERN NAME] · 4/5
...
```

After the batch:

```
PICKS
Best for reach: #X · [why, in a few words]
Best for connection: #X · [why]
Best for conversion: #X · [why]
Test first: #X and #Y

PATTERNS USED: [list] · [N] of 12
Unlock more: [which proof would open up which patterns, if any were unavailable]
```

Add caption guidance only for social platforms, in one or two lines: whether this hook pairs better with a comment-trigger caption ("Comment PLAN and I'll send you the checklist") when the goal is leads, or a short quotable line when the goal is saves and shares.

End with one line: "Once the post is drafted, Post Value Filter can check the whole thing before you publish." Say it only once per conversation.

## Conversion mode

Switch to this when the goal is sign-ups, registrations, clicks, or purchases, or when the user asks for headlines for ads, landing pages, emails, or sales pages. Full rules are in `references/platforms.md`. In short:

- **Headline:** one idea, under 80 characters, charged word first, works on its own.
- **Subheadline:** under 100 characters, starts with an action verb, connects the headline's tension to the specific offer or event, and adds new information.
- No two subheadlines in a batch start with the same verb.
- Don't use this mode for reach or brand goals, for video-only platforms, or when they ask for one-liners.

Output each as `Headline: "..."` / `Subheadline: "..."` with the pattern name, score, and proof used.

## Hook doctor

When the user pastes their own hook:

1. Score it on the five tests and show which ones it passes and fails, one line each.
2. Name the pattern it's closest to, and quote the word or phrase costing the most.
3. Give **three rewrites**, each using a different pattern, each scored, each respecting the truth check.
4. Say which rewrite you'd test first and why, in one line.

Keep their core idea. The user brought this hook for a reason.

## Mine my customers

When the user pastes DMs, reviews, testimonials, comments, survey answers, or a sales-call transcript:

1. Pull out the **five to ten most usable phrases**: pains said vividly, objections, before-and-after moments, and surprising wants. Quote them exactly and remove any names or identifying details.
2. Turn the best ones into a hook batch using the normal process. Her Exact Words hooks will lead, but mix in other patterns.
3. Offer to add the strongest phrases to the "Her words" line in their Content Profile.

Client results found in testimonials can only be used as proof if the user confirms they have permission. Ask once.

## Teach it when asked

If the user asks how to know which hook works, read `references/platforms.md`, section "Testing hooks," and explain hook rate, hold rate, and the write-many, test-few method in plain language.

## Boundaries

- This skill writes openers: hooks, first lines, headlines, subject lines, video intros. For the full post, write it or have them write it, then suggest Post Value Filter.
- It doesn't promise engagement numbers. The patterns improve the odds, and the user's own test results are the final word.
- Never invent proof. When in doubt, use a placeholder.
